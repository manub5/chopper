# Distribution Kubuntu — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer une archive installable de Chopper pour un premier essai sur Kubuntu 26.04.1.

**Architecture:** Conserver l'application dans son dossier décompressé et préparer son environnement avec l'installateur Bash existant. Un petit outil Python standard crée le raccourci KDE après accord ; un autre produit un ZIP depuis un commit Git propre. Aucun changement du moteur audio.

**Tech Stack:** Bash, Python 3.12 standard, uv, Git, Desktop Entry/XDG, pytest.

**Spec:** `docs/superpowers/specs/2026-11-08-distribution-kubuntu-design.md`

## Global Constraints

- Cible : Kubuntu 26.04.1 ; architecture et compatibilité à confirmer sur la machine destinataire.
- Une commande `bash install.sh`, puis lancement depuis le menu KDE ; application conservée au lieu de décompression choisi.
- Sources audio, exports, préférences et caches existants préservés ; poignée inchangée.
- Internet requis à l'installation et éventuellement à la première analyse ; pas de promesse hors ligne totale.
- Ne créer aucun dossier dans le compte utilisateur sans confirmation de l'emplacement.
- Aucun sudo pour l'application ; modifications système annoncées et confirmées.
- Textes utilisateur et commentaires de code en anglais, échanges et commits en français.
- Aucun secret ou chemin personnel dans les sources ; aucun retrait des hooks existants.
- Livrables dans `dist/`, jamais de publication GitHub automatique.
- Après chaque tâche : tests, résultat, puis attendre la validation utilisateur avant la suivante.

## Review Focus

1. Chemins avec espace, apostrophe, dollar ou pourcentage : lancement sans interprétation shell ni field code involontaire (tâches 1–2).
2. Relance sur une installation de développement : ne pas enlever ses outils ni écraser ses fichiers étrangers (tâches 1–2).
3. Réseau, sudo ou synchronisation en échec : pas de faux succès ni raccourci vers une installation incomplète (tâches 1–2).
4. Raccourci existant, lien symbolique ou destination non inscriptible : préserver les fichiers, annoncer l'échec sans supprimer l'application (tâche 2).
5. ZIP fabriqué après modifications ou contenant un lien suivi : refuser plutôt qu'embarquer une version ambiguë ou des fichiers externes (tâche 3).

## Fichiers et responsabilités

- `install.sh` : consentements, prérequis, synchronisation et lanceur local.
- `scripts/install_desktop.py` (nouveau) : génération sûre et consentie du fichier Desktop Entry.
- `scripts/build_release.py` (nouveau) : ZIP, somme et traçabilité du commit.
- `tests/test_install.py` : tests Bash isolés existants, à étendre.
- `tests/test_desktop_install.py`, `tests/test_release.py` (nouveaux) : tests sans réseau ni écriture réelle dans le compte.
- `docs/INSTALL_KUBUNTU.md` (nouveau) : installation, déplacement, retrait manuel et recette cible en anglais.
- `README.md`, `docs/DECISIONS.md`, `docs/HISTORIQUE.md` : consignes et limites actualisées.

## Task 1: Installation verrouillée et lanceur sans synchronisation

**Files:** modifier `install.sh`, `tests/test_install.py`, `README.md`, `docs/HISTORIQUE.md`.

**Interfaces:** consomme `pyproject.toml` et `uv.lock` ; produit `./chopper` marqué `# Generated by install.sh for Chopper.`. Le lanceur exécute `"${DIR}/.venv/bin/chopper" "$@"`, après vérification de son existence, sans uv au lancement.

- [ ] **1. Tests rouges :** étendre la sandbox pour simuler l'exécutable `.venv/bin/chopper` et les réponses utilisateur. Assertions : `uv sync --locked --no-dev --inexact`, lock inchangé, arguments et chemin spécial transmis intacts, absence d'appel uv au lancement. Ajouter refus du téléchargement uv et de sudo (aucun téléchargement/apt), échec curl et échec sync (statut non nul, pas de message Done, pas de nouveau lanceur), réinstallation et sentinelles étrangères intactes. Vérifier le refus du lanceur étranger avant toute modification système.
- [ ] **2. Rouge :** `uv run pytest -q tests/test_install.py` ; constater les échecs correspondant au comportement demandé.
- [ ] **3. Implémenter :** précontrôler les collisions, annoncer effets et demander confirmation avant téléchargement uv ou apt. Télécharger l'installateur uv dans un fichier temporaire avec échec propagé avant son exécution, jamais `curl | sh`. Conserver son installation officielle et expliquer ses chemins avant accord. Synchroniser avec les options ci-dessus : installation fraîche sans outils dev, installation existante sans suppression de paquets supplémentaires. Générer le lanceur avec citation correcte des arguments ; conserver l'alias ancien existant sans le modifier.
- [ ] **4. Vert :** `bash -n install.sh` puis `uv run pytest -q tests/test_install.py` puis `uv run pytest -q`. Aucun téléchargement réel ni sudo pendant les tests. Mettre à jour README et historique avec résultats et effets de bord.
- [ ] **5. Commit :** `Fiabilise l'installation et le lancement sans synchronisation`. Hooks actifs, montrer les résultats et attendre validation.

## Task 2: Entrée dans le menu KDE

**Files:** créer `scripts/install_desktop.py`, `tests/test_desktop_install.py`, `docs/INSTALL_KUBUNTU.md` ; modifier `install.sh`, `tests/test_install.py`, `README.md`, `docs/HISTORIQUE.md`.

**Interfaces:** `desktop_entry(launcher: Path) -> str`, `install_desktop(launcher: Path, data_home: Path) -> Path` dans `scripts/install_desktop.py`. CLI `--launcher PATH`, destination déduite de `XDG_DATA_HOME` absolu ou de `~/.local/share`. Confirmation interactive de la destination complète AVANT mkdir/écriture, défaut non. Refus/EOF = installation locale utilisable sans raccourci ; erreur d'écriture = message explicite et statut non nul, aucun faux succès.

- [ ] **1. Tests rouges :** entrée avec `Type=Application`, `Name=Chopper`, `Terminal=false`, `Categories=AudioVideo;Audio;`, `Icon=audio-x-generic`, marqueur `X-Chopper-Generated=true` et chemin Exec absolu correctement échappé. Tester espace/apostrophe/dollar/backslash/pourcentage, rejet des retours ligne et du signe égal interdit dans le chemin exécutable. Vérifier XDG absolu et défaut, rejet d'un XDG relatif, refus sans mkdir, EOF sans blocage, réinstallation identique, refus fichier étranger et symlink (même cassé), erreur d'écriture sans altération de l'ancien fichier.
- [ ] **2. Rouge :** `uv run pytest -q tests/test_desktop_install.py tests/test_install.py` ; échecs d'absence du helper ou de son intégration.
- [ ] **3. Implémenter :** bibliothèque standard uniquement ; pas de `sh -c`, pas de traitement du chemin comme commande shell. Échappements Desktop Entry selon la référence officielle, `%%` pour les pourcentages littéraux. Installation du fichier `applications/chopper.desktop` par écriture temporaire et remplacement après contrôles ; ne remplacer qu'une entrée portant le marqueur ET `Type=Application`/`Name=Chopper`, jamais un symlink. Appeler le helper avec `.venv/bin/python` seulement après succès de la tâche 1. Le consentement d'un helper doit précéder toute création dans le compte ; un raccourci refusé ne fait pas échouer l'installation locale.
- [ ] **4. Vert :** `uv run pytest -q tests/test_desktop_install.py tests/test_install.py` puis suite complète. Tester l'entrée avec `desktop-file-validate` si disponible et vérifier les arguments décodés avec Qt dans les tests (sans ouvrir l'application). Documenter conservation du dossier, réinstallation après déplacement, retrait manuel du seul raccourci généré, maintien des samples/préférences et récupération en cas d'erreur.
- [ ] **5. Commit :** `Ajoute un raccourci KDE après confirmation`. Hooks actifs, présenter résultats, attendre validation.

## Task 3: Archive traçable et recette sur Kubuntu

**Files:** créer `scripts/build_release.py`, `tests/test_release.py` ; modifier `docs/INSTALL_KUBUNTU.md`, `README.md`, `docs/DECISIONS.md`, `docs/HISTORIQUE.md`.

**Interfaces:** `build_release(repo: Path) -> tuple[Path, Path]` ; CLI `python scripts/build_release.py`, sortie uniquement dans `repo / "dist"`. Nom `chopper-{version}-{short_commit}-linux.zip`, racine identique sans `.zip`, somme `.zip.sha256`. Lire version et octets depuis HEAD ; inclure `RELEASE.txt` généré avec SHA complet et version.

- [ ] **1. Tests rouges :** dépôts Git temporaires indépendants, sans réseau ni hooks. Vérifier fichiers obligatoires, contenu exact de LICENSE/uv.lock, commit complet, SHA-256 correcte et racine unique. Refuser index/worktree suivis sales, version avec séparateur de chemin et symlinks suivis dans les chemins livrés. Ignorer les fichiers non suivis : injecter `.env`, audio, `.venv`, `dist`, vérifier leur absence ; une seconde génération ne doit ni inclure le premier ZIP ni écraser une sortie étrangère.
- [ ] **2. Rouge :** `uv run pytest -q tests/test_release.py` ; échec faute de constructeur.
- [ ] **3. Implémenter :** standard Python (`subprocess` sans shell, `zipfile`, `hashlib`, `tomllib`). Liste blanche explicite : `src/chopper/`, `scripts/install_desktop.py`, `install.sh`, `pyproject.toml`, `uv.lock`, `LICENSE`, `README.md`, `docs/INSTALL_KUBUNTU.md`, `docs/FINAL_VALIDATION.md`, et `RELEASE.txt` généré. Lire uniquement les blobs Git de HEAD ; refuser les modes non réguliers dans cette liste. Construire archive et somme dans des fichiers temporaires dans dist puis publication sans écraser une sortie différente ; si sortie existante identique, la conserver. Aucun fichier source modifié, aucun accès au contenu personnel. Dates ZIP fixes et ordre des entrées stable pour reproductibilité d'un même commit.
- [ ] **4. Vert :** `uv run pytest -q tests/test_release.py` puis `uv run pytest -q` ; `uv run ruff check src tests scripts`, `uv run ruff format --check src tests scripts`, `uv run mypy src tests scripts`, `uv run bandit -qc pyproject.toml -r src scripts -ll` et `git diff --check`. Ne pas modifier les hooks pour contourner une alerte.
- [ ] **5. Documentation :** distinguer les tests simulés de la validation réelle encore attendue. Recette : relever version Kubuntu/architecture, installer depuis une nouvelle extraction, accepter/refuser le raccourci, lancer depuis KDE, analyser un morceau puis préécouter/exporter, fermer/relancer. Ne pas promettre toutes architectures ni tous pilotes. Référence d'installation depuis l'archive : `bash install.sh` dans son dossier.
- [ ] **6. Commit :** `Prépare une archive Linux traçable pour le prêt`. Exécuter ensuite le constructeur depuis cet état propre, vérifier somme et contenu réels, scanner la plage de commits avec gitleaks. Une revue finale indépendante portera sur les trois tâches ; ne pas réclamer de revue par tâche.
