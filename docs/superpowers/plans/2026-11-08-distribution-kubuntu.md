# Distribution Kubuntu — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer une archive installable de Chopper pour un premier essai sur Kubuntu 26.04.1.

**Architecture:** Conserver l'application dans son dossier décompressé et préparer son environnement avec l'installateur Bash existant. Un petit outil Python standard crée le raccourci KDE après accord ; un autre produit un ZIP depuis un commit Git propre. Aucun changement du moteur audio.

**Tech Stack:** Bash, Python 3.12 standard, uv, Git, Desktop Entry/XDG, pytest.

**Spec:** `docs/superpowers/specs/2026-11-08-distribution-kubuntu-design.md`

## Global Constraints

- Cible : Kubuntu 26.04.1 ; architecture et compatibilité à confirmer sur la machine destinataire.
- Une commande `bash install.sh`, puis lancement depuis le menu KDE ; application conservée au lieu de décompression choisi.
- Sources audio, exports, préférences et caches existants préservés ; poignée inchangée.
- Internet requis à l'installation et éventuellement à la première analyse ; pas de promesse hors ligne totale.
- Ne créer aucun dossier dans le compte utilisateur sans confirmation de l'emplacement.
- Aucun sudo pour l'application ; modifications système annoncées et confirmées.
- Textes utilisateur et commentaires de code en anglais, échanges et commits en français.
- Aucun secret ou chemin personnel dans les sources ; aucun retrait des hooks existants.
- Livrables dans `dist/`, jamais de publication GitHub automatique.
- Après chaque tâche : tests, résultat, puis attendre la validation utilisateur avant la suivante.

## Review Focus

1. Chemins avec espace, apostrophe, dollar ou pourcentage : lancement sans interprétation shell ni field code involontaire (tâches 1–2).
2. Relance sur une installation de développement : ne pas enlever ses outils ni écraser ses fichiers étrangers (tâches 1–2).
3. Réseau, sudo ou synchronisation en échec : pas de faux succès ni raccourci vers une installation incomplète (tâches 1–2).
4. Raccourci existant, lien symbolique ou destination non inscriptible : préserver les fichiers, annoncer l'échec sans supprimer l'application (tâche 2).
5. ZIP fabriqué après modifications ou contenant un lien suivi : refuser plutôt qu'embarquer une version ambiguë ou des fichiers externes (tâche 3).

**Décisions et limites de clôture :**
- Validation par étape conservée conformément aux règles du projet ; coût :
  une confirmation utilisateur par étape, plutôt qu'une exécution sans pause.
- Vrai consommateur Desktop Entry GLib, pas un faux parseur Qt ; coût : le menu
  KDE natif et son cache restent à tester sur la cible.
- Environnement et projet uv imposés localement ; coût : les redirections uv
  personnalisées ne s'appliquent pas à cet installateur, workflow manuel disponible.
- `env --` nécessaire pour les pourcentages ; coût : nécessite coreutils/PATH
  du bureau, normal sur Kubuntu. Source Git bornée à `.py`/`py.typed` ; coût :
  futures ressources à autoriser explicitement après revue.
- Matériel, modèle, pilotes, authenticité de la chaîne de téléchargement et
  garanties juridiques non établis par les tests : recette cible, HTTPS officiel
  et licences conservées, sans audit matériel/sécurité/juridique implicite.
- Cases de clôture mises à jour après preuves des tâches ; coût : état transitoire
  du plan incomplet, sans effet sur le logiciel. Espace isolé et livrables conservés
  pour l'essai utilisateur, pas de nettoyage destructif ou de push automatique.
